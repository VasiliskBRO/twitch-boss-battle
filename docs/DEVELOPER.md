# Документация для разработчиков

Технические подробности: устройство частей 1–7, API модулей, решения по ТЗ, симулятор, лимиты Твича.
Краткая инструкция для игроков и стримеров — в [README](../README.md).

```bash
node --test     # все тесты
node demo.js        # веса навыков для дракона и голема, 8 игроков, сводка черт по 1000 игрокам
node demo_cards.js  # раздачи для 5 seed, сценарий «карта → фаза 2 → момент стримера»
node simulate.js --scenario engaged,lurkers,mixed  # симулятор боёв (часть 5)
node play.js --fast      # поиграть самому в терминале: вы стример и игрок, вокруг боты
node demo_points.js      # 20 боёв с файловым хранилищем очков, вывод !очки и !топ (часть 6)
node auth.js             # разовая авторизация бота (часть 7)
node bot.js              # бот на канале; --console [--fast] — без Твича; --loadtest 300 — нагрузка
```

Общие соглашения:
- `rng(min, max)` — внедряемый генератор, целое из `[min, max]`. Дробные броски — через `rand01(rng)` (`src/rng.js`).
- Всё, что «выдаётся на бой» (класс, стихия, личный навык, редкость, черты), детерминированно выводится из
  хеша `battleId:userId[:соль]` (`src/hash.js`: FNV-1a + перемешивание fmix32). Общий rng и `Math.random`
  для этого не используются, поэтому выход/перезаход ничего не перебрасывает.
- Числа — в `src/config.js`, каталоги — в `src/data/*.js` (подключены в конфиг как `PERSONAL_SKILLS.CATALOG` и `TRAITS`).
  Любую функцию можно вызвать с собственным `config` (последний аргумент).

## Запуск на Твиче — пошагово (часть 7)

Всё ниже делается один раз. Команды вводятся в **PowerShell** (Пуск → «PowerShell»).

### Что понадобится
- **Node.js 20 или новее.** Проверка: `node --version` (должно быть `v20…` или больше). Если нет — скачайте LTS с nodejs.org.
- **Аккаунт стримера** — канал, где будет игра.
- **Отдельный аккаунт для бота** — обязательно. С аккаунта стримера бот пока не работает: он игнорирует
  свои сообщения и поэтому не увидит команды стримера (`!босс`, `!карта`). Отдельный бот-аккаунт — например,
  `BossBattleBot` — к тому же безопаснее и понятнее зрителям.

### Шаг 1. Аккаунт бота
Зарегистрируйте новый аккаунт на twitch.tv (в приватном окне браузера, чтобы не выйти из своего).
Включите на нём двухфакторную защиту (Настройки → Безопасность) — без неё Твич может не дать создать приложение.

### Шаг 2. Приложение в консоли разработчика (Client ID и Secret)
1. Откройте **dev.twitch.tv/console** и войдите (можно под своим основным аккаунтом).
2. **Applications → Register Your Application.**
   - **Name:** любое уникальное, например `boss-battle-ваш-ник`.
   - **OAuth Redirect URLs:** ровно `http://localhost:3000/callback`
   - **Category:** Chat Bot. **Client Type:** Confidential.
3. **Create**, затем **Manage** у приложения:
   - **Client ID** — скопируйте;
   - **New Secret** → появится **Client Secret** — скопируйте сразу (он показывается один раз).
   Никому их не показывайте.

### Шаг 3. Сделайте бота модератором
В чате своего канала (под аккаунтом стримера) напишите: `/mod имя_бота`.
Модератор может отправлять 100 сообщений за 30 секунд, а обычный аккаунт — только 20 и не чаще раза в секунду.
VIP (`/vip имя_бота`) тоже подойдёт.

### Шаг 4. Установка
```powershell
cd C:\Projects\интерактив
npm install
```
Должно закончиться строкой `found 0 vulnerabilities`.

### Шаг 5. Файл .env (секреты)
```powershell
Copy-Item .env.example .env
notepad .env
```
Заполните: `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` (из шага 2), `TWITCH_CHANNEL` — имя канала
(как в адресе twitch.tv/имя), `BOT_USER_NAME` — логин бота. Сохраните. Файл `.env` никуда не выкладывайте.

### Шаг 6. Авторизация бота (один раз)
```powershell
node auth.js
```
Откроется браузер (если нет — скопируйте ссылку из консоли). **Войдите под аккаунтом БОТА** (удобно в
приватном окне), нажмите **Authorize**. В консоли появится `✅ Готово: токен для @имя_бота сохранён в data/tokens.json`.
Токен сам обновляется во время работы — повторять этот шаг не нужно (только если удалите токен или смените скоупы).

Бот просит такие разрешения (скоупы): `user:read:chat` — читать чат, `user:write:chat` — писать в чат,
`user:read:moderated_channels` — узнать, модератор ли он в вашем канале.

### Шаг 7. Проверка без Твича
```powershell
node bot.js --console --fast
```
Пишите строки как в чате: `@стример я: !босс`, затем `аня: !join`, `боря: !join`, `аня: !я`.
`@мод имя: …` — от модератора. `--fast` — время в 10 раз быстрее. Выход — `выход` или Ctrl+C.

### Шаг 8. Запуск на канале
```powershell
node bot.js
```
В консоли: `подключено к чату` и роль бота. В чате канала напишите `!босс` — бой начнётся.
`!ботстатус` (стример и модераторы) покажет аптайм, длину очереди и режим лимитов.
`!поддержатьигру` (любой зритель, раз в минуту на весь чат) — ссылка на донат автору игры; адрес в `TWITCH.supportUrl`.
Остановка — **Ctrl+C**: бот сохранит бой, допишет важные сообщения и отключится. Если запустить снова
в течение 20 минут, бой продолжится («🔄 Бот перезапущен, бой продолжается»).

### Работа 24/7 на сервере (VPS с Linux)
1. Установите Node.js 20+ и скопируйте папку проекта (без `node_modules`).
2. **Авторизацию делайте на своём компьютере** (шаг 6: redirect идёт на `localhost`) и скопируйте на сервер
   `.env` и `data/tokens.json`.
3. На сервере:
   ```bash
   cd ~/boss-battle && npm ci --omit=dev
   chmod 600 .env data/tokens.json
   npm install -g pm2
   pm2 start bot.js --name boss-bot
   pm2 save && pm2 startup     # автозапуск после перезагрузки сервера (выполните команду, которую покажет pm2)
   pm2 logs boss-bot           # живой лог; полный — в logs/bot.log
   ```
   Вместо pm2 можно systemd: `ExecStart=/usr/bin/node /home/user/boss-battle/bot.js`,
   `WorkingDirectory=/home/user/boss-battle`, `Restart=always`, `KillSignal=SIGINT`.

### Обновление
Остановите бота (`pm2 stop boss-bot` или Ctrl+C), замените файлы проекта, **не трогая** `.env`, `data/` и `logs/`,
выполните `npm ci --omit=dev` (или `npm install`), `node --test` и запустите снова.

### Типовые проблемы
- **Бот молчит.** Проверьте, что `node bot.js` пишет `подключено к чату`; что в `.env` верное имя канала;
  что команды начинаются с `!`. В `logs/bot.log` видно ошибки. Убедитесь, что бот не забанен в канале.
- **«без прав модератора (лимиты строже)».** Напишите в чате `/mod имя_бота` и перезапустите бота.
  VIP бот определяет по значку своего первого сообщения в чате.
- **Сообщения пропадают.** При наплыве бот сам выбрасывает менее важные сообщения (сводки, прогресс лобби)
  и считает их: `!ботстатус` → «удалено за сессию». Ход боя (заголовки, итоги) не выбрасывается никогда.
  Если удаляется много — сделайте бота модератором.
- **Токен истёк / «не удалось обновить токен».** Запустите `node auth.js` заново (под аккаунтом бота).
- **`redirect_mismatch` в браузере.** В консоли разработчика Redirect URL должен быть ровно `http://localhost:3000/callback`.
- **Порт 3000 занят.** Поменяйте `TWITCH.authPort` в `src/config.js` и Redirect URL в консоли разработчика.
- **«Нет data/tokens.json».** Сначала шаг 6.

### Расхождения ТЗ с документацией Твича и решения
1. **Не IRC, а EventSub + Send Chat Message API.** Документация Твича называет этот способ предпочтительным
   (dev.twitch.tv/docs/chat); IRC — устаревшим. Отправка через API сразу говорит, принято ли сообщение
   (`is_sent`, `drop_reason`). Скоупы соответственно `user:read:chat`, `user:write:chat` (вместо `chat:read`, `chat:edit`).
2. **Лимиты** совпадают с ТЗ: 20 за 30 с и 1 в секунду для обычного аккаунта, 100 за 30 с для модератора/VIP/стримера;
   повтор того же текста в течение 30 с Твич отбрасывает (`msg_duplicate`) — очередь дописывает « ·2».
3. **Роль бота при подключении.** Токен бота не видит, VIP ли он. Модераторство проверяется запросом
   (скоуп `user:read:moderated_channels`), VIP — по значку в первом же сообщении бота; до этого — «осторожный» режим.
4. **Отправка от имени бота.** В Twurple `sendChatMessage` по умолчанию шлёт от имени стримера — используем `asUser(бот)`.
5. **Общий чат (shared chat).** Сообщения, пришедшие из соседнего канала, игнорируются (`TWITCH.ignoreSharedChat`).
6. **Без связи** очередь держит high и normal не дольше 10 с (как в ТЗ), остальное удаляет. Правило «high не удаляются
   никогда» действует при перегрузке очереди.
7. **Права 600** на `data/tokens.json` в Windows работают лишь частично; на Linux-сервере — полностью (см. `chmod` выше).
8. **Лимит отряда.** В части 2 стояла заглушка `PLAYER_LIMIT: 50` — из-за неё нагрузочный тест сначала пускал в бой
   только 50 из 300 зрителей. Поднято до 1000. Прошлые прогоны симулятора на 100 игроков фактически были на 50.

## Часть 2. Игроки и классы

```js
import { joinPlayer, pickSingleTarget, findMostWounded } from './src/players.js';
import { rollAction, regenMana, takeDamage, tickDowned } from './src/player_actions.js';

const registry = new Map();
const res = joinPlayer(registry, battleId, userId, displayName, currentTurn, battleStarted, { boss });
// res = { ok, player, reason }, reason: joined | already_joined | full

const action = rollAction(res.player, 'навык', rng);           // ничего не меняет
const auto   = rollAction(res.player, 'атака', rng, { auto: true }); // автодействие, 50% силы
```

- **Класс выдаётся случайно** при `!join` и не выбирается: `assignClass(battleId, userId)` — хеш пары с солью
  `class`, веса `CONFIG.CLASS_WEIGHTS` (по умолчанию 25/25/25/25). Смены класса нет; перезаход и выход класс
  не меняют. Для тестов и инструментов есть `buildPlayer(battleId, userId, name, classId, { boss })`.
- `joinPlayer`: одна запись на `userId`, повторный вход ничего не меняет. Новичок посреди боя получает
  `activeFromTurn = currentTurn + 1` и полное HP. Лимит — `CONFIG.PLAYER_LIMIT` (`full`).
  Порядок внутри: `assignClass → createPlayer (assignElement) → assignPersonalSkill → assignTraits → applyTraits`.
- `renderJoinInfo(player)` (≤ 500): «@ник, ты 🛡️ Воин 🔥 | ❤️ 120/120 | 🔷 30/30 | ✨ Особый: Контрудар (редкий) |
  🎁 Дар: … | 💀 Проклятия: … | !атака !навык !особый». `renderPlayerStatus` (`!я`) — тот же формат с текущими HP,
  маной, откатом и статусом.
  Если босса ещё нет, навык `null` — выдать позже через `assignPersonalSkillsForAll(registry, boss, battleId)`.
- Дескриптор `rollAction`: `{ kind, name, damageType, element, amount, crit, manaCost, fallback, missed }`.
  - `kind`: `damage | heal | healAll | taunt | none`.
  - `amount`: для `damage` — урон; для `heal`/`healAll` — **доля макс. HP цели** (0.35 = 35%); для `taunt` — множитель урона по воину.
  - `fallback: true` — действие заменено (нет маны на навык → !атака; у хиллера нет маны на Лечение → Искра света).
  - `missed: true` («Дрожащие руки») — `kind: 'none'`, `amount: 0`, но `manaCost` сохраняется: мана тратится.
- `takeDamage` возвращает реально снятое HP (с учётом `damageTakenMult`); `healPlayer` — реально восстановленное (без перелечивания).
- `tickDowned` — раз в начале хода: упал на ходу t → встаёт на t + `reviveTurns` (по умолчанию 2) с 30% HP.
- `pickSingleTarget(players, rng, { mode: 'random' | 'topDamage', turn })` — цель одиночной атаки босса среди
  живых активных, с весом `mods.bossTargetWeight`.

## Часть 3. Личные навыки (!особый)

```js
import { rollPersonalAction, startCooldown, tickCooldowns, renderPersonalSkill } from './src/personal_skills.js';

const d = rollPersonalAction(player, boss, rng);
// { kind: 'personal', skillId, name, rarity, effects: [...], fallback: false, missed }
// на откате: дескриптор !атака с fallback: true
```

- Выдача: навык — взвешенно по `hash(battleId:userId:skill)`, редкость — по `hash(battleId:userId:rarity)`.
  Вес = 10 × множители правил из каталога (`getSkillWeights(boss, player)`), пул — класса игрока
  (класс уже выдан `assignClass`). Навык и черты стабильны для пары (battleId, userId).
- Редкость: обычный 70% (×1.0), редкий 25% (×1.25), эпический 5% (×1.6 и +1 ход к длительностям).
  Масштабируются только поля из `scale` каталога; Берсерк масштабирует коэффициент `k`, потолок ×5 общий.
- `effects` — массив эффектов из `EFFECT_TYPES` (`src/effects.js`). К полям из ТЗ добавлено одно:
  `delayedDamage.damageType` (части 5 нужен тип урона Метеора).
- **Контракт отката для части 5:** после применения `!особый` вызвать `startCooldown(player)`
  (3 хода, у эпического 2, плюс «Тугодум»); `tickCooldowns(player)` — ровно один раз в начале каждого хода;
  навык готов при `cooldowns.personal === 0`. При `missed` откат тоже запускается (как трата маны).

## Часть 3. Черты

- `assignTraits(player, battleId)` → `{ gift, curses: [a, b] }`: все черты ранжируются по `hash(battleId:userId:traitId)`;
  дар — первая допустимая классу положительная, проклятия — следующие допустимые отрицательные из ещё не занятых групп.
- `applyTraits(player, traits)` пересчитывает `maxHp`/`maxMana` (с округлением), ставит полные HP и ману,
  записывает `player.traits` и `player.mods`. Множители перемножаются, добавки складываются, override побеждает.
- Модификаторы учитываются в `rollAction` (урон, лечение, крит, промах, цена маны), `regenMana`, `takeDamage`,
  `tickDowned`, `startCooldown`, `pickSingleTarget`.

## Часть 4. Карты стримера

```js
import {
  createStreamerState, parseCardCommand, playCard, onPhaseChange, consumePendingCard, tickTurn,
  renderHand, toJSON, fromJSON,
} from './src/streamer_cards.js';

const state = createStreamerState(rng);              // 3 разные карты, ≥ 1 помощь и ≥ 1 помеха
const r = playCard(state, parseCardCommand(text), userId, { isBroadcaster, isModerator }, turn, nowMs, rng);
// r = { ok, card, effects, announce, reason, reply, applyAt }
//   ok      → отправить r.announce в чат
//   !ok     → отправить r.reply, если он не null (посторонним по умолчанию молчим)
```

- Каталог: `src/data/streamer_cards.js` (12 карт, числа там же), подключён как `CONFIG.STREAMER.CATALOG`.
  Настройки `CONFIG.STREAMER`: `handSize`, `minTurnsBetween`, `momentSeconds`, `handVisibility` (public | private),
  `allowMods`, `replyToUnauthorized`. Дескриптор карты: `{ id, name, emoji, kind, effects, announceText }`.
- Эффекты карт — новые типы в `EFFECT_TYPES`: `blockNextBossAttack`, `healAll`, `restoreManaAll`, `trueDamageBoss`
  (`canKill: false`), `bossDamageBoost`, `bossDamageTakenReduction`, `silenceRandomClass`, `healBoss`,
  `swapBossAffinities`, `teamDamagePenalty`; плюс существующие `teamDamageBoost` и `reviveAll`.
  Для `swapBossAffinities` в модуле босса есть `swapWeaknessResistance(boss)`.
- `canPlay(state, userId, roles, currentTurn, nowMs, index?)` → `{ ok, reason }`, причины по порядку проверки:
  `notAllowed`, `handEmpty`, `badIndex`, `alreadyPlayedThisTurn`, `cooldown`.
- **Контракт для части 5:**
  1. После `playCard` забрать карту: `consumePendingCard(state)` → `{ card, effects, applyAt, playedTurn }`.
     `applyAt: 'thisTurn'` — применить в этом ходу; `'nextTurnStart'` (сыграна в момент стримера) — в начале следующего.
     Пока карта не забрана, новую сыграть нельзя.
  2. Для каждой новой фазы босса вызвать `onPhaseChange(state, newPhase, nowMs, rng)` → `{ card, messages, privateMessages }`:
     `messages` — в чат, `privateMessages` — в консоль бота (только при `private`). Удар через две фазы — два вызова.
  3. В конце каждого хода — `tickTurn(state, nowMs)`.
  4. Для «Проклятия» класс выбирает часть 5 (случайный из участвующих): у модуля карт нет реестра игроков.
- Состояние — простые данные: `toJSON`/`fromJSON` переживают перезапуск бота, включая открытое окно момента
  (оно хранится как абсолютное время `momentUntilMs`).
- `renderHandCompact(state, currentTurn)` (≤ 120): «🃏 [1]🛡️ [2]😡 [3]🎯 — можно играть» / «… — пауза ещё 2 хода» /
  «🃏 рука пуста»; при закрытой руке — «🃏 3 карты — …» без названий.
- `showHand(state, roles, nowMs)` — команда `!рука` (стример; модераторы при `allowMods`), не чаще раза
  в `handCommandCooldownSeconds` (10 с): полная рука с короткими описаниями (поле `short` каталога).
  При закрытой руке в чат — только число карт, подробная рука — на консоль бота.

## Часть 5. Движок боя (`battle/`)

```js
import { createBattleEngine, fromJSON } from './battle/engine.js';

const store = createFileStore('data/points.json');          // часть 6; по умолчанию — в памяти
const engine = createBattleEngine({ config, rng, now, store }); // now() — миллисекунды
send(engine.handleMessage({ userId, displayName, text, roles: { broadcaster, moderator } }));
setInterval(() => send(engine.tick()), 1000);               // сам закрывает лобби и разрешает ходы
// send(messages): { text, to: 'chat' | 'console', priority: 'low' | 'normal' | 'high' }[]
//   console — только закрытая рука стримера; low (вступления, прогресс лобби) можно отбросить при перегрузке

save(engine.toJSON());                                      // в любой момент
const restored = fromJSON(saved, { config, rng, now, store }); // после перезапуска; просроченный ход разрешится на первом tick
const result = engine.getState().result;                    // после phase === 'ended' — для части 6
```

| Файл | Что |
|---|---|
| `battle/engine.js` | Фасад, разбор команд, лобби, таймеры |
| `battle/turn.js` | Начало хода и разрешение по шагам 1–10 |
| `battle/effects.js` | Семантика эффектов карт, личных навыков и навыков босса |
| `battle/render.js` | Сообщения: заголовок и итог хода, лобби, победа/поражение, `!я` |
| `battle/state.js` | Состояние, сериализация, `buildResult` |

- **Команды.** Регистр и лишние пробелы не важны. Бот отвечает только на `!я` (раз в 20 с на игрока), `!карта`
  (только при успехе), `!рука`, `!join`, `!очки`, `!топ`. На `!атака`, `!навык`, `!особый` ответа нет.
  `!босс` и `!стоп` — стримеру и модератору.
- **Опечатки** (`battle/suggest.js`): «@ник, такой команды нет. Может, ты про !атака?» — только если
  команда близка к нашей (до 1–2 правок, перестановка букв, оборванная команда, набор в другой раскладке
  «!fnfrf», русское «!джоин»). Чужие команды (`!uptime`, `!so`, `!top`) — без ответа. Команды стримера подсказываются
  только стримеру и модераторам, и только когда они имеют смысл в этой фазе. Кулдаун 30 с на зрителя и 5 с общий,
  priority `low`, выключается `BATTLE.suggestCommands = false`.
- **`!join`** без класса (текст после него игнорируется). Ответ — `BATTLE.joinReplyMode`:
  `auto` и `batch` — раз в `joinBatchSeconds` (5 с) сводка «⚔️ В отряд вступили: @a, @b. Напиши !я для получения
  информации», разбитая на сообщения ≤ 500; `always` — «@ник, ты в отряде! Напиши !я…» каждому; `off` — молчать.
  Повторный `!join` молчит. Приоритет — `low`.
- **Заголовок хода** заканчивается строкой руки (`renderHandCompact`); при закрытой руке каждый ход ещё подробная
  рука на консоль.
- **Сообщения хода:** заголовок + итог (1–2) + момент стримера, всего не больше трёх. При смене фазы или конце боя итог сжимается в одно сообщение.
- **Длительности.** Эффекты тикают в конце хода. Эффект, созданный до атаки босса, действует в этом ходу и ещё `turns − 1`. Эффект атаки босса действует `turns` ходов со следующего.
- **Вклад и поддержка (для части 6).** Движок пишет `stats.support` (см. ниже) и `stats.contribution` — вклад,
  накопленный по ходам с потолком `POINTS.turnContributionCap` × макс. HP босса на каждый ход. В `result`
  приходят `bossMaxHp` и статы игроков с `support` и `contribution`.
- **Конец боя.** При переходе в `ended` (кроме отмены) движок один раз вызывает `processBattleResult` и склеивает
  итог боя с начислением в одно сообщение, чтобы на ход оставалось не больше трёх сообщений.
- **Числа.** Секции `BATTLE`, `BOSS_SKILL_EFFECTS`, `BOSS_PHASE_DAMAGE_MULT`, `SIM_TARGETS` в `src/config.js`.
- **Тесты.** `tests/battle/` (`resolution` — порядок и эффекты, `engine` — лобби, команды, сохранение, golden, инварианты, `points_integration` — !join, рука, поддержка, вклад, очки). Golden-журнал лежит в `tests/golden/battle10.txt`. Перегенерация после намеренных изменений: `UPDATE_GOLDEN=1 node --test`.

### Симулятор

```bash

```

Таблица по размерам отряда: победы / поражения / wipe, средние ходы, HP босса при поражении, доля павших, победы по архетипам и слабостям. Затем сравнение с `SIM_TARGETS` и подсказки, какие числа крутить. Таблица по классам: средний вклад, средние очки участника, вклад класса относительно среднего и его состав (урон / лечение / принятое / поддержка); при отклонении больше ±15% — подсказка, какой вес вклада крутить или что дело в уроне класса. В каждом бою проверяются инварианты: HP и мана в [0, max], нет NaN, ходов не больше maxTurns+1, сообщения не длиннее 500. При нарушении симулятор печатает seed и выходит с кодом 1.

## Часть 6. Очки, рейтинг и звания (`points/`)

```js
import { createFileStore, processBattleResult, handleCommand, computeAwards } from './points/index.js';

const store = createFileStore('data/points.json'); // load при создании; повреждённый файл поднимается из .bak
processBattleResult(result, store, config, nowMs);  // { awards, newTitles, messages }; второй раз с тем же battleId — skipped
handleCommand(event, store, config, nowMs, cooldowns); // !очки (30 с на игрока), !топ (60 с общий)
```

- **Вклад** = damage × 1.0 + healing × 1.2 + absorbed × 0.5 + support × 1.0 (`POINTS.weights`), за ход не больше
  10% макс. HP босса. Лечение — только реально восстановленное HP.
- **Поддержка** (`stats.support`, пишет движок): лишний урон от Благословения (поровну между источниками бустов) и
  Раскола брони; предотвращённый Магическим барьером и Щитом света урон; 3% / 2% макс. HP босса за реальное
  срабатывание Антимагии (сорван бафф или снята броня) и Очищения (снят дебафф или отражён иммунитетом).
  Карты стримера (Боевой клич, Щит) поддержку никому не дают.
- **Награды.** Участник — `activeTurns ≥ 2` (автоатаки не считаются), боты из `excludeUserIds` исключены.
  50 за участие + доля пула 100 × N по вкладу + 100 MVP + 50 за добивание; при поражении ×0.4; отмена — ничего;
  округление вниз, минимум 1.
- **Хранилище.** Один JSON-файл: атомарная запись (`.tmp` → rename), копия предыдущей целой версии в `.bak`,
  отложенная запись (2 с) и принудительная после каждого боя. Обработанные `battleId` хранятся — повторное
  начисление невозможно. Пример после 20 боёв — `data/points.sample.json` (`node demo_points.js`).
- **Звания** — `points/data/titles.js`: бои (10/50/150), победы (1/5/15/40/100), MVP (1/5/15), добивания (5/20),
  лечение и поддержка за всё время. Показывается звание с наибольшим приоритетом; новые называются в итоге боя.
- **Рейтинг** — по `totalPoints`; при равенстве выше тот, кто раньше появился (`firstSeenAt`).

### Решения по неоднозначностям частей 2, 4–6
1. **Ответ на `!join`** — по решению заказчика короткий: сводка «Напиши !я для получения информации», а не
   `renderJoinInfo` каждому. Режим `auto` работает как `batch` (сводка раз в 5 с), поэтому 30 входов за 10 с дают 2–3 сообщения.
2. **Итог боя и начисление** — одно сообщение (лимит три сообщения на ход): «🏆 Победа! … Добивающий удар: @x. MVP: … Свои очки: !очки».
   Отдельный формат `renderAwardsSummary` из ТЗ сохранён и используется, когда нужен сам по себе.
3. **`!очки` без записи** — «@ник, у тебя ещё нет очков: заходи в бой через !join» (добавлено обращение по нику).
4. **Боты** из `excludeUserIds` сравниваются без учёта регистра и по `userId`, и по нику.
5. **Перекрытие эффектов в поддержке.** Лишний урон от Благословения и Раскола брони считается каждый относительно
   итогового урона удара; при одновременном действии их доли немного перекрываются.

### Решения по неоднозначностям части 5
1. **Бонус фазы.** «Выстрел в слабое место» с фазы 2 даёт ×2.25 вместо ×1.5, как в ТЗ части 3, а не ×1.5 × 2.25. `rollPersonalAction` отдаёт итоговый `mult`, и движок не применяет бонусы фазы и Берсерка повторно.
2. **Проценты.** В каталогах они хранятся долями, поэтому «1 + pct/100» из ТЗ реализовано как `1 + pct`.
3. **Промах личного навыка** бросается один раз, внутри `rollPersonalAction` (поле `missed`).
4. **Карта из «момента».** Её забирает шаг 1 следующего хода, и движок кладёт её в `queuedMomentCard`, чтобы применить в начале хода, который идёт за розыгрышем. Иначе по ТЗ она бы потерялась.
5. **Щит** блокирует атаки по игрокам (single, aoe, debuff). Бафф босса на себя Щит не тратит.
6. **Наложение эффектов.** Барьеры перемножаются, а из нескольких Щитов света берётся самый сильный.
7. **Урон навыка босса** = доля из `DAMAGE_VALUES[kind]` × `power` навыка × maxHp цели × `getBossDamageMult` × барьеры × 0.5 при провокации. Провокация уменьшает урон только одиночной атаки.
8. **Бафф `dmg_up`** («Кровавое безумие») есть в каталоге боссов, но не в ТЗ. Он реализован как damageDealt = 1 + power на 2 хода.
9. **Найден и исправлен баг части 1.** `tickStatuses` затирал множитель урона архетипа. Теперь `damageDealtMult` хранит только статусы, а архетип и фаза учитываются в `getBossDamageMult`. Откаты босса вынесены в `tickBossCooldowns`, а `addStatus` действует сразу.

## Решения по неоднозначным местам ТЗ

Часть 4:
- При `handVisibility = private` скрывается только содержимое руки (и название карты, добавленной в момент).
  Сыгранная карта объявляется по названию — иначе чат не узнает, что произошло.
- `canPlay` принимает номер карты 6-м параметром: без него нельзя вернуть причину `badIndex`.
- `parseCardCommand('!карта 9')` возвращает 9: номер вне руки отсекает `canPlay` (`badIndex`), и стример получает подсказку.
- `tickTurn` закрывает окно момента только по переданному `nowMs`: окно открывается в конце хода,
  и безусловное закрытие в том же `tickTurn` убило бы его сразу.

Части 2–3:

1. «Неудачник» убирает только случайный крит; гарантированный крит «Меткого выстрела» остаётся.
2. Задержка Метеора не считается длительностью: эпический Метеор тоже падает в конце следующего хода.
3. У «Града стрел» число ударов (3) не масштабируется, масштабируется урон каждого удара.
4. Проценты в описаниях округляются вниз: Контрудар (редкий) 62.5% → «62%».
5. В `!я` значок стихии хиллера не показывается (у него нет стихии, holy — тип класса).
6. Хеш — FNV-1a с финальным перемешиванием: чистый FNV-1a даёт перекос, когда ключи отличаются только солью в конце.

## Часть 1. Босс — контракт хода

- `tickStatuses(boss)` — раз в начале каждого хода: тикает статусы **и откаты навыков** босса.
- `pickTelegraph(boss, rng)` ставит откат `cooldown + 1`, поэтому навык недоступен ровно `cooldown` ходов.
  Если всё на откате, берётся разблокированный навык с наименьшим откатом (по возможности не повтор).
- `applyDamage` может перевести босса через несколько фаз за один удар (1 → 3).
- Вся случайность — через внедрённый `rng`; одинаковый `rng` даёт одинакового босса, HP и последовательность атак.
  Исключение — `boss.id`: в нём `Date.now()`, чтобы id были уникальны между боями.
